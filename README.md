# UMM —— UE 通用 Mod 管理器

给 Unreal Engine 游戏用的本地 Mod 管理器：把散落各处的 Mod 归档成一个「模组库」，
按 游戏 / 分类 整理，用勾选框一键启用或停用，并精确记录每个 Mod 到底往游戏目录里放了哪些文件夹。

> 当前版本 **V0.2**。功能仍属早期，配置格式与界面都可能变。

## 它解决什么问题

UE 游戏的 Mod 大多是一堆 `.pak` / `.ucas` / `.utoc` 文件（也有 `.dll` / `.lua` / `.ini`）。
手动启停通常要拆包、复制、自己记着放过什么，想删又怕删错别的 Mod。

UMM 的做法是把**「库」和「游戏目录」分开**：

1. **导入**：Mod 的压缩包（`.zip` / `.rar` / `.7z`，自动解压）或文件夹，完整复制到
   「备份路径」下的 `游戏\分类\Mod名\` —— 库里始终留着一份完整的
2. **启用**：把该 Mod 的文件夹从库复制到游戏的 Mod 目录；同名文件夹已存在时自动改成
   `xxx_1`、`xxx_2`，**不覆盖**已有内容
3. **停用**：只删掉「启用那一刻记下来的那几个文件夹」—— 不会误删别的 Mod，
   也不会碰你手动放进游戏目录的东西

判断「这是一个 Mod」的依据是文件夹里含有 `.pak`、`.ucas`、`.utoc`、`.dll`、`.lua`、`.ini`。
递归查找时遇到压缩包会先解压再找，并处理一个压缩包里装了多个 Mod 变体（分叉）的情况。

## 界面

| 区域 | 作用 |
|---|---|
| 游戏列表 | 可登记多个游戏，每个游戏记录：游戏名 + 游戏程序路径 + 该游戏的 Mod 目录 |
| 模组分类 | 每个游戏下自建分类，用来给 Mod 分组 |
| 模组列表 | 勾选框启用 / 停用；上方搜索框可过滤 |
| 模组详情 | Mod 名称、原始名称、是否已启用，以及预览图 |
| 顶部 / 底部 | 游戏路径与 Mod 路径、备份路径（模组库位置）、已启用 Mod 数量 |

## 数据放在哪

- **配置**：`%LocalAppData%\UMMData\UMMData.json`
  （游戏列表、每个 Mod 的启用状态与「已复制文件夹名」、备份路径）
- **模组库**：界面下方指定的「备份路径」，结构为 `游戏\分类\Mod名\...`
- 更换备份路径时，程序会把旧库**递归复制**到新位置，不会丢 Mod

## 构建

- Visual Studio（需要 **.NET Framework 4.8** 开发工具）
- 打开 `UMM.sln` 直接生成即可；NuGet 包按 `packages.config` 自动还原

主要依赖：Newtonsoft.Json、SharpCompress（读 zip / rar / 7z）、ZstdSharp.Port、
Costura.Fody（把依赖嵌进 exe，输出单文件）。

## 已知限制

- 仅 Windows（WPF，.NET Framework 4.8）
- 主要逻辑集中在 `UMM\MainWindow.xaml.cs`，尚未拆分
- 压缩包解压依赖 SharpCompress，个别非标准归档可能解不开
- **「启动游戏」按钮尚未接上实现**（点了没反应）；登记的游戏程序路径目前只是记录信息
- 版本 V0.2：数据结构与界面都可能变，升级前建议备份 `UMMData.json`
